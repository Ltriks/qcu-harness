# QCU external Client entry

This directory owns the first external Client migration slice for the locked official baseline `639ed015397290b3745d163aafe02ffee4aa3f84`. The package contributes one localized entry to the pre-existing `conversation.session.header.actions` list; it neither declares a new slot nor replaces the app root. Official locale and slot registrations are disposable Cordis effects. All visual styles belong to the mounted entry.

The entry is available only where the official conversation header renders its Session action list. It is absent in empty/new-conversation layouts with hidden header chrome. Session identity supplies the local React lifetime key and a locally computed SHA-256 namespace for result handoff. The raw Session identity never leaves the application Client through this bridge. The official `useSessionRetainInfo` selector closes the view when the Session leaves the main view, even if another consumer retains the Session. The entry does not read Session contents, projections, attachment fields, filenames, document identifiers, or thesis text.

## Native availability

The only transport is the optional `window.dshDesktop.qcu` v1 interface from `../native-contract.ts`: `available`, `open`, `setBounds`, `close`, and `back`. Exact version and method validation rejects absent, older, expanded, and malformed objects. `available() === true` means the fixed isolated QCU panel is enabled and its private Host service is bound. Availability is checked on mount and again after an explicit open click. A compatible bridge that is not yet ready shows a localized “Retry QCU” control: retry checks availability on the same mounted entry, without opening a view, polling, or issuing a task request. A separate explicit open click is still required after readiness succeeds. Missing or incompatible bridges have no retry or fallback; the pure official baseline remains a disabled “QCU · not enabled” entry. A failed native close also suppresses retry and preserves the restart-required lockout.

Each click creates an unpredictable ephemeral occurrence identifier prefixed by a fixed-format Session digest. Only that scoped identifier and CSS-pixel bounds of the entry's own empty placeholder cross the bridge. Neither a Session identifier nor a service URL crosses it. The native implementation alone owns isolated navigation and the task document. There is no generic browser, iframe, webview, provider registration, command execution, upload control, or fallback task page in this Client.

The HTML dialog contains only the frame title, status, Back, and Close/Cancel controls. It uses top-layer placement and sends the empty content rectangle as native bounds. The Client observes its own rectangle and viewport resize/scroll events; it never inspects another plugin's DOM. The frame uses existing DSH theme tokens and a desktop overlay-top CSS inset. The earlier claims that this avoids header clipping, guarantees visible frame controls, or follows a published overlay inset remain unverified in a real desktop; this readiness change does not alter or validate geometry.

## Lifecycle

Duplicate clicks do not create a second occurrence. Closing before availability resolves never calls native open. Closing during native open immediately revokes that occurrence and closes it again if its completion arrives late. A newer occurrence cannot be closed by an older completion. A pending native close must finish before another open. Session replacement, main-view retention loss, plugin removal, and component teardown retire the mounted controller. Native errors are reduced to fixed locale-owned messages; raw errors cannot expose private service details.

“Close panel” and “Cancel opening” revoke a view and its ephemeral context; neither claims to stop a running server-side check. A failed native close prevents reopening and asks the user to restart the desktop app. The eventual native adapter must also close views when the owner renderer/window disappears, because renderer-side cleanup alone cannot establish teardown after a crash or failed IPC.

## Build and checks

Run `npm run build:client`. `scripts/build-client.mjs` uses maintained esbuild to emit `lib/client.js` and its source map in the official `window.__ModuleLoader__.load({ id, factory })` lazy-CJS format. The factory identifier comes from package metadata. React stays external and resolves from the official browser module table. CSS is text inside the bundle and creates no factory-time DOM effects. The script rejects any other runtime external. Official Client packages are development-only type references; they are not bundled runtime imports. This reproduces the locked repository-local format, not a published external UI build preset or marketplace protocol.

Run `node --test tests/client-*.test.mjs` after building and `tsc --project tsconfig.client.json --noEmit`. Tests exercise the shipped artifact bytes with React and synthetic jsdom state, plus a transport-independent controller. They cover absence/incompatibility, cold-start readiness retry without Session remount, no implicit open, duplicate clicks, cancellation at both async stages, stale availability after teardown, stale Session and main-view lifetime, disposal, geometry, Back, fixed diagnostics, and style/listener cleanup. Dialog geometry and native IPC are synthetic. These checks do not establish Electron behavior, native panel isolation, macOS/Windows window integration, visual theme contrast, real document handling, or server cancellation.

The header contributes one `Tools` selector with a named `Thesis check` choice. Expanding the selector does not check a document or open a native view. Choosing the task uses the existing controller and five-method capability. This is one owned menu with one supported task, not a generic plugin registry; further tasks must join the same selector rather than append header buttons.
