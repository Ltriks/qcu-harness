# QCU 专家团与专家库

版本 `0.2.0-pilot.3`，线协议3，DSH `0.2.0-rc.2` / Cordis `4.0.4` 插件。专家独立保存通用职责和技能方法，专家团选择成员、补充分工，并配置协作流程。模型复用 DSH 默认设置，不另存 API Key。

## 使用

1. 在“专家库”新建或编辑专家，保存名称、简介、通用职责和最多4项已安装技能。同一专家可以加入多个团队。
2. 在“专家团”新建团队，从专家库选1–6位成员。团队分工只补充本团队的要求；通用职责仍在专家库维护。
3. 选择独立评审后汇总、顺序接力或自定义依赖，指定汇总专家和1–3人的并发上限。所有成员须汇入最终结果，循环依赖无法保存。
4. 在“开始任务”填写任务和材料，预览精确模型、专家分工、技能正文与请求上限，确认后启动。
5. 在“运行记录”回看各专家和最终汇总结果，下载待教师复核的Markdown报告。
6. 失败、停止、中断记录可下载部分报告；“未完成”不能视为完整结论。选择已结束历史后先下载JSON数据备份，再预览清理，核对工作区、记录与数量并明确确认。取消不删除，清理不能撤销。备份不能导入或执行；成功清理后旧任务预览全部失效。

界面自动选择唯一或上次合法工作区。编辑未保存时切换会提示保存或放弃；专家和团队可以复制、归档、恢复。仍被使用的专家不能归档。导出的团队文件包含所需专家，导入时创建新对象，不覆盖已有配置。

## 评审分工与篇幅

pilot.3 为每次调用明确传入真实的最终汇总身份：评审成员仅给本职意见，最终汇总成员整合任务交付，不让每人重复写一份总报告。默认建议评审正文180字符、汇总600字符（数字和标点计入，空白不计）；任务明确指定篇幅时按任务要求。预览显示这些规则，超出建议长度时界面和Markdown都提示，保留完整原文，不截断答案、不自动重试。旧版专家资料无需重置，既有历史不会重生成；长篇历史也可看到提示。

这些是提示与可观察的篇幅检查，不能保证所有模型都遵守篇幅或分工；真实输出仍需教师复核。

## 数据与运行边界

配置和历史位于所选工作区 `.qcu-expert-teams/state.json`，存储schema2。首次读取schema1会先保存原始字节备份，再转换为独立专家与团队引用，保留原团队、职责、技能、依赖、修订和历史。迁移后的数据不能直接由旧schema1版本读取；回退时须同时恢复相应旧数据备份。

修改专家资料用于之后的任务；已有运行保留职责、技能、模型和输入快照。配置发生变化后，旧预览和确认失效。每位专家最多一次模型请求、6000输出令牌；停止、超时、失败、停用或重启后不自动重新运行。

技能只加载说明作为方法参考，不执行脚本、MCP或连接器。结果是否正确、是否适合课堂仍由教师复核。上限为120位专家、20个团队、50次运行和8,000,000字节存储（含配置）；运行记录页显示当前条数与序列化字节，接近容量时提示手动备份和清理。归档可恢复，历史清理只删除明确选择且已结束的记录，不会自动删除。

## 安装与验证

新固定包默认禁用，需单独启用。QCU教师离线profile中的既有插件没有发布到npm；官方在线安装器会重新解析它们并可能返回404。本机采用教师离线组件布局和官方profile接口安装，保留原组件。当前市场白名单未扩充，不代表在线市场已可安装此插件。

本轮仅交付本地候选，没有安装、部署或真实模型调用。核心、官方运行时和浏览器验收均使用合成状态，真实原生界面、文件选择器、模型与教学质量需另外验收。详细清单及匿名自编材料见仓库 `docs/qcu-expert-teams-hardening.md`。

构建：`rtk proxy node hub/plugins/qcu-expert-teams/build.mjs`。

打包：`rtk proxy python3 hub/plugins/qcu-expert-teams/pack.py /path/to/new-output`。
