## 开关加正常重启（没有移除包）

真实 Chrome 官方 Plugins 页面把 Bundle 开关从 true 改为 false，读到官方“下次启动生效”提示。当前运行时仍有 CSV 入口、任务接口200，符合 HMR 关闭的官方 restart-required 行为。正常退出已核实归属本轮的进程，再以同一官方 CLI/profile 启动：CSV 入口不存在、接口404、owned工作目录为空。无需删除包或重写组件配置。

随后在官方页面把开关从 false 改为 true，当前运行时仍是无入口/404；正常退出重启后入口恢复，合成个人规则再次检查为4行/7个问题。全程测试暗色15px样式保留，无页面错误。这与此前“包移除+重启”是两条独立已通过的路径。

关闭开关不是即时撤销。本版任务页已明确提示：如插件页显示下次启动生效，先点击“取消并撤销”终止本次授权，再正常退出重启，并确认入口消失。不能因开关外观变为关闭就声称当前权限已经撤销。未启用 HMR，也不宣称热停用通过。

使用官方 CLI 对退出后的测试 profile 安装准确的本机 tgz，顺序为 prototype.5→prototype.6→prototype.5→prototype.6。CLI add 的同包版本替换已验证；官方 Plugins UI 仍不承诺自动或原地升级，不能把 CLI 演练当作 UI 自动更新验收。没有重装基础依赖或修改兼容性门槛。

每个阶段启动同一 profile，在真实页面重新选择合成 CSV、输入保留的个人规则文件、明确确认后检查，均为4行/7个问题；取消及离开后owned目录为空。合成 CSV、个人规则文件、Host配置、官方暗色/15px样式的哈希快照完全一致。最后恢复 .6。

这里证明的是规则文件和配置保留。页面暂存的规则编辑、文件选择、结果和逐文件授权本来不跨启动保存；重启后必须重新选择和确认。没有声称未保存草稿持久化，没有恢复过期授权。

## 可取得的官方来源证据

官方 GitHub API 当前确认 dsh-v0.2.0-rc.2 标签指向固定639ed015397290b3745d163aafe02ffee4aa3f84，干净checkout中的CLI及Web Bundle版本也是0.2.0-rc.2。官方registry rc.2包元数据的repository指向同一官方仓库，提供dist.integrity及registry签名。实际安装的Web Bundle cordis.patch.yml与固定checkout对应文件逐字节相同；这只证明这一静态资源相同，不证明所有构建产物的精确来源commit。

但两个registry元数据均未提供gitHead或来源attestation。Registry签名没有在本轮做密码学验证，即使有效也不能代替构建来源证明。因此只确认官方tag、版本、仓库及包完整性标识，继续保留“实际registry tarball由哪个精确commit构建尚未证明”的限制。不凭同名版本虚构对应。
