# Mac report saving and task entry

The running predecessor was verified as the isolated development candidate. Its local report URL returns 403 without the native view's browser authorization; no report contents were read in this check. User feedback confirmed file-picker cancel/reselection and print preview. These are user-confirmed checks, not automated GUI acceptance.

Two defects prevented a usable save path. Chat tools returned local URLs which an assistant could turn into download links, but official Markdown delegates HTTP links to browser/external navigation rather than the private QCU view. Separately, the task summary linked straight to a download even though native download admission requires the matching report to be the current loaded document. The report page lacked a save control.

The summary now opens the report. The report exposes `Save HTML report`; the existing native save dialog still requires a fresh user activation and the exact matching report/download route. Cancel leaves the report available for another click. Repeated/script-only requests do not acquire another save dialog. Previously generated reports receive the online control when viewed, while their stored/exported bytes remain unchanged. Print hides the save controls. Tool responses and the dedicated persona now give panel guidance and counts instead of local URLs. No native capability, origin allowlist, attachment admission, or ordinary chat navigation was widened.

The official `conversation.session.header.actions` slot hosts one localized `Tools` selector. Its task is explicitly named `Thesis check`. Expanding the selector does not open a task or authorize a check. Selection opens the existing narrow native panel and closing returns to the conversation. Empty/new-conversation layouts which hide the official header still do not show this slot. The scoped implementation adds no task/plugin registry and does not change the app root or sidebar.

Future business features should contribute named choices to the same owned selector, with task-specific authorization and capabilities. QCU names the office environment, not each task. Plugin/Skill installation and enablement belong in a separate management surface; this restricted profile currently disables those management plugins. Re-enabling management or supporting another task therefore requires a separate reviewed profile change, not another header button or a broader native URL API.

Validation on macOS: isolated Client build and typecheck; 30 Client/controller/tool-guidance tests; 12 Python engine/server tests with synthetic DOCX, repeated downloads and old-report byte preservation; 17 dedicated Host lifecycle/policy tests; 71 mocked Electron task-panel tests, including cancel/retry and activation consumption. A reconstructed cumulative patch must apply to the pinned baseline and its test slice must match. These checks do not certify real native save-dialog behavior.

The active candidate was deliberately preserved. New Client, plugin/persona and Python resources require a coordinated normal app exit and replacement with this newly built bundle before native retesting. Do not hot-replace resources while a task is active. After loading the new candidate, use `Tools → Thesis check`, create a synthetic report, enter it, cancel Save once, then save again and verify one dialog per fresh click. The user need not rerun shell commands; deployment can be automated when the Mac is connected and no task remains active. Save-dialog cancel/retry and the new selector's appearance remain pending real GUI acceptance. Formal packaging/signing/Windows remain outside this change.
