# Host 与 Python 的共同生命周期

本次开发从公开 Git 主线 `756b7331b2eaf91aff5340c62cedaf5261af7876` 开始。该主线已经合入 Mac 网页检查完成反馈；此修复不改变反馈、论文引擎、两工具、受控报告 URL 或固定入口策略。

## 原故障与修改

原 Host 启动 Python 时忽略 stdin。实际合成 QcuService 启动后，仅强杀其 Node Host，Python 仍监听且保留 `server.lock`/`bridge.json`；新 Host 保守拒绝接管一个仍存活的记录 PID。这种拒绝不应通过杀掉记录中的 PID 来绕过。

Host 现在固定传入 `--parent-stdin`，持有这个子进程 stdin 管道的写端，不写入任何数据或凭据。Python 从读端观察 EOF 或读错误，停止自身服务；普通数据不被解释为指令，也不记入日志。正常的认证关闭仍保留。

EOF 后优先正常停止服务。若启动或服务循环卡住，观察器等待 2 秒，再给本进程清理最多 1 秒，随后仅退出自身进程。这个上限依赖操作系统和 Python 线程正常获调度；不是对内核挂起的保证。正在处理的请求可能被中断，不保证异常终止时仍完成报告。

服务记录使用独占创建。清理只删除本次创建且文件身份、权限、内容仍匹配的记录；替换、不可信、未知或其他实例的记录保留。普通启动仍保留保守的已死 PID 残留恢复路径，不增加远端关闭、按 PID 杀进程、进程组终止或服务接管。

## 使用与维护边界

- Host 与 runtime 源码必须作为匹配组件构建，不能只换 Host 后继续使用不识别新参数的旧 Python 服务
- 直接运行 Python 且不传 `--parent-stdin` 时保留独立服务语义；stdin 关闭不会自动停止它
- 旧版本已经残留的活服务不会被新版本自动收养或终止。先通过它原有的受控关闭路径结束；不确定身份时停下核实，不凭记录 PID 操作
- 管道写端仅由当前 Host 持有；不得向其他进程显式复制该句柄。任意同权限 Node 代码或恶意句柄复制不属于隔离保证
- 如清理期间文件被替换或底层 I/O 异常，服务退出但记录可能保留，后续启动仍可能拒绝。不可为了自动恢复而放宽所有权校验
- Linux 合成跨进程验证不能替代 Mac/Windows 原生验收。此修复不引入新持久凭据、用户配置或权限

## 复现入口

先按 [REBUILD](REBUILD.md) 重建匹配官方源码与包，并运行三个类型检查和包构建。包内 `test:host` 会包含父管道 Python 子套件；它使用临时目录、合成 DOCX 与真实 Node/Python 子进程。Linux 测试监督器只回收自己创建的子孙进程，生产代码不使用该测试机制。

测试源码位于 `packages/qcu-thesis-workbench/tests/test_parent_lifetime.py`、`host-parent-lifetime.spec.ts` 与 `qcu-service.spec.ts`。执行日志留在开发 checkout 的忽略目录；测试结果和命令见 [本轮验证](LIFECYCLE-VALIDATION.md)。安装发布前仍须单独完成平台、升级和数据恢复门槛。
