# 安装团队接入原专家团工作室

2026-11-12。纠正上一轮把团队当作主会话技能使用、却未接进原工作室的问题。用户的使用入口应是专家团工作室；市场和能力库负责发现、安装与进入工作室。

## 已实现

- 工作室 Host 从官方技能注册表和当前 profile 的官方包清单发现五类迁移团队，读取安装包的 `manifest.json` 和角色资源；逐项核对来源记录中的角色字节数与 SHA256。
- 已安装但未启用的包也显示，不因为未注册技能而消失；标为待启用或重开，不能发起任务。只从官方清单中的当前 profile 安装目录补读资源，不接收用户输入的安装路径。
- 原“专家团”列表同时显示自建团队和已安装团队，标注原生代理团队；不把七人团队截断为六人，也不将其写入旧文字评审配置。
- 原“专家库”中展示安装包成员，成员数计入列表计数，可查看完整职责并返回所属团队。安装包职责只读，自建专家保持原来的编辑功能。
- 原工作室中选择团队、填写任务和参考资料，再打开对应原生任务会话。创建独立会话并预填内容，由用户发送后执行，不覆盖已有草稿或自动读取上传文件。
- 市场/能力库的团队启动按钮改为进入工作室；移除能力库中另一套原生任务填写入口。工作室未更新或尚未就绪时明确提示，不静默退回技能调用。
- 原文字评审仍使用旧调度器、模型确认、运行记录和导出，工作区数据结构不变。

## 使用与剩余差异

在 .19 保存工作，正常退出并重开 QCU，然后进入：

**专家团 → 专家团工作室 → 选择工作区 → 深度研究团队 / KET备考团队。**

不需要重新安装已安装团队。点击成员可查看职责；原“专家库”也可找到这些成员。

新原生团队的检索、代码与多角色执行仍交给原生会话，过程和产物暂在那里查看；没有冒称已统一到旧“运行记录”，也没有将原生请求量伪装成旧评审的一人一次调用。真实模型端到端与工具效果尚待验收。下一阶段再统一运行过程、任务记录和产物。

底层包保留 DSH 技能注册作为装载与模型发现机制；工作室通过团队定义适配器识别成员和职责。用户不再需要从技能列表手动调用这些团队。
