# 教师预装版可行性核对（2026-10-21）

用户反馈原三步离线套件不适合教师与年长校领导，优先希望解压即用；备选去掉市场、以技能及插件已经安装的状态交付。本轮是可行性核对和隔离原型，不替换昨日正式归档的内测候选。

## 结论：pilot

建议教师交付采用“预装九个能力包、默认启用、无市场、单启动入口”。包安装和依赖准备由发布者完成，用户不选择脚本、不执行包管理、不手动开插件。Windows 优先验证解压后双击；Mac 使用相同预装能力，是否可直接从解压目录启动，要单独完成原生启动、签名与下载后首次打开验收。需要时由网管一次部署，教师以后只双击图标。

市场是否保留并不决定能否预装。去掉市场是教师版的简化建议，原管理员版和历史发行包保留。本轮未修改它们。

## 已验证

- 昨日 Windows 官方包提取的原始 x64 应用载荷可以从隔离目录运行 CLI；不是只能通过 NSIS 安装器调用。尚不能据此声称 Windows GUI 便携版已验收。
- 今日另建纯净预装模板：只复制此前自建测试环境中的九个固定产品包及原生 CLI，生成新的标准 profile 清单；不复制用户 home、凭据、会话、缓存、pnpm 项目元数据和锁文件。
- 将模板从构建位置实际移动到另一个含中文与空格的目录。清单使用固定版本，无开发机绝对安装来源；飞书 CLI 路径在新位置由准备程序绑定。
- 使用官方 DSH0.2.0-rc.2 Mac ARM64 运行时，在网络阻断下真实导入九个模块，从官方 Skills 注册表读取七项技能正文。没有调用 npm/pnpm、没有缓存目录、没有网络尝试、没有市场目录。
- 结果：`.work/preinstalled-relocation-poc/result.json`，日志：同目录 `relocation-smoke.log`。这是同一台 Mac 上的路径迁移与运行时验证，不是第二台真机、原生 GUI 或模型效果证明。

## 交付设计及剩余工作

1. 发布者生成经过校验的无账号预装模板，分别配上官方原样客户端与对应平台的原生 CLI。模板和应用不可直接使用本机绝对路径。
2. 单个启动入口在首次运行时自动复制模板到本人的独立可写数据目录，绑定本机 CLI 路径，再启动客户端；以后保留自己的配置和工作记录。首次复制不运行包管理器。
3. 发布前完成技能和插件启用配置；飞书功能仍需本人的授权和选定文档。已安装、已启用与已经授权可读取不能混淆。
4. 模型连接由维护人员在首次交付时完成，或接入学校已具备的模型服务。若缺模型服务/账号，预装不能使模型回答自动可用；不得随公共包分发个人 API Key 或登录态。
5. 保留原厂应用签名。本轮没有创建或检查可用于自有启动器的 Developer ID/公证能力。Mac 系统会检查下载应用的签名、公证及首次打开；不能承诺所有电脑完全无确认提示，也不能把“在构建机能运行”当作分发验收。

系统边界依据：[Apple Gatekeeper](https://support.apple.com/guide/security/gatekeeper-and-runtime-protection-sec5599b66df/web)、[Apple 首次打开应用](https://support.apple.com/en-au/102445)、[Electron 代码签名](https://www.electronjs.org/docs/latest/tutorial/code-signing)。平台是否能达到单入口，是待验证的产品行为，不从 Electron 标签推定。

最小下一步验收：从干净的目标系统解压，移动目录后仅双击启动入口，确认无终端、无包安装与启用步骤，七项技能和两个插件可发现；由维护人员配置模型后跑一项合成备课任务，正常退出重开保留数据。覆盖 Windows x64（原生硬件与 ARM64 仿真分列）和 Mac ARM64。若 Mac 首次分发不满足此体验，交付给网管一次部署的预装版，不要求教师处理系统安全设置。

本次可行性检查结束时尚未生成新的教师版完整压缩包、尚未开发或验收原生单入口。随后用户明确要求Windows打包测试，已进一步生成Windows0.1.0-rc.2教师预装包，原生准备检查通过，用户确认打开DSH正常界面且课程工作台和Skill插件可见，后续状态以[Windows交付记录](teacher-windows-release.md)为准。截至2026-10-21，Mac保持本页原型验证范围；0.1.0-rc.1套件保留原样。
