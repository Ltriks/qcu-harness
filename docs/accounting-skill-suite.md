# 会计系教学技能包示例：交付与使用

2026-11-16。已通过现有投稿审核、发布预览及签名流程发布到内网市场，目录 revision **12**。条目名 **会计系教学技能包（示例）**，版本 `0.1.0-pilot.1`。

## 为什么这样组织

科系包作为统一安装与维护入口，具体技能作为任务入口，适合老师第一次配置以及同一科系批量推广。首轮一个包只含相关、低权限、可统一维护的四项教学方法。老师按需选择，不会因安装包而同时运行所有任务或调用模型。

包内技能共用版本与启停。若以后成员需要不同权限、维护人或更新节奏，应拆成独立产品，再提供安装集合；本轮不提前实现跨包安装事务和自动回滚。

## 包内内容

| 入口 | 用途 |
|---|---|
| 会计系技能选用入口 | 根据需求选择下列方法 |
| 会计分录实训 | 业务、科目、借贷方向、题目与教师参考 |
| 凭证审核模拟 | 计算/抄录差错、科目疑点与资料不足分类 |
| 报表勾稽练习 | 试算、利润、期末权益及报表关系 |
| 课堂案例设计 | 课时活动、分层支架与评价要点 |

固定虚构案例含六笔业务，明确不含税费、折旧及利润分配。确定性验算得到资产12500、负债1000、期末权益11500、本期利润1500，试算借贷双方均14200。脚本只校验这一套参考数据，不保证模型生成的新题正确。

## 老师怎么使用

其他机器：工具市场刷新，搜索上述条目，查看成员与影响，确认安装，再单独确认启用。一个归档、一个组件注册五个入口，所有成员都在投稿中明确声明。完整安装包未重新打包。

`.19` 已从实际签名市场下载安装并独立启用；配套成员展示为市场 `16.11`、主题 `0.3.0-pilot.4`。正常退出并重开后进入“我的技能”，搜索“会计”，选择一项填写任务，打开草稿并自行发送。成员可分别收藏/固定，管理安装始终指向母包。

旧界面可显式调用：

```text
/qcu-accounting-journals
为基础会计入门学生设计两笔虚构业务分录练习。
学生题目与教师参考分开，不含税费和折旧。
```

这个示例适合向领导展示“统一分发、成员独立使用”的技术机制。会计系教师仍需确认实际课程、教材/准则口径、题目及输出样例；不把安装验证写成正式教学采用。

## 技术验证与边界

- Skill Creator验证五项入口格式；静态投稿检查15个归档成员、零错误、零不支持项。
- 官方随包ASAR验证五项发现、内容与资源、冲突不覆盖、停用全部移除、篡改在注册前失败。
- Node相关回归及固定案例正/负例通过；发布器七项测试覆盖成员完整声明、路径、摘要、旧单技能及已有工作台例外。
- 发布器补齐严格的多技能静态清单校验，保留一个组件、原安装确认、签名和来源校验。拒绝“实际五项、仅声明一项”。旧有工作台例外保留；服务端代码变更已备份，管理端发布后HTTP 200，公开下载服务未停止。
- 内网目录签名及归档大小/SHA256由`.19`独立核对，隔离与现用官方SDK安装均通过；默认安装停用，再明确启用，冷启动取得五项技能及资源，原组件字节一致。
- 真实React浏览器验证成员展开、独立草稿、管理母包、收藏与首页成员启动。浏览器使用合成宿主，不冒充原生窗口点击验收。
- 本轮模型调用0、`teacherApproved=false`。真实模型产出、原生点击与教师教学效果未验收。不增加工具权限、账套连接、申报接口或后台任务。
