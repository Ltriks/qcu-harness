# QCU 市场发布通路验收说明（P15）

本轮目标：管理员在 Web 完成人工审核与发布，老师在 DSH 的 QCU 市场刷新后看到同一精确版本，并自行决定安装和启用。

**当前是本地开发候选，尚未部署到现有 Hub 或 mini。** 本地合成测试使用真实网页、签名目录、HTTP 下载和官方 rc.2 的通信机制；安装与启用业务效果使用隔离模拟，不等于原生 DSH 验收。正式环境的管理员密码、签名密钥尚未设置。

## 验收前准备

由维护者完成部署准备，提供管理页地址、普通老师的 Hub 地址与经过核验的市场安装包。管理员页面仍只监听发布机本机；需要远程操作时使用经确认的连接入口。不要在普通公开下载目录中保存账号、密钥、源码交付材料或审核日志。

维护者先核对旧产品清单和安装包，在首次签名目录中保留已发布产品；不得以空目录直接替换老师正在使用的目录。老师首次需要安装固定了本团队公钥的 P15 市场发行并正常重启 DSH；此后普通上架不需要每次重装市场。未经这一步更新的旧市场，仍沿用原来的内置审核目录。

这里的“签名”是 QCU 团队对市场目录做的内部验签，不是 Apple 应用签名，无需 Apple 开发者账号或付费证书。老师仍使用官方 DSH 的安装与确认流程。

准备一个实际完成审核、符合当前单组件契约的测试产品。不要使用真实学生资料、API Key 或其他凭据作为样例。自动测试中的 Synthetic 条目仅供隔离测试，不得上架真实市场。

## 管理员验收

1. 使用 `qcu-admin` 登录，选择开发者提供的完整 handoff 文件夹，点击“上传并检查”。应显示材料检查结果；失败的材料不能批准或发布。
2. 在审核前填写并保存市场说明：用途、场景、使用前提、示例、权限、已测与未测边界、来源。核对源码、许可与测试证据后，再填写审核理由并逐项确认。批准后不能继续修改已批准的说明；需要修改时提交新修订、重新审核。
3. 单独确认生成发布候选。此时老师端不应出现新产品，不能把“本机候选已生成”当作已发布。
4. 打开“预览公开发布”，核对产品、版本、包摘要、审核记录及目录变化，再勾选并确认发布。正常结果应明确显示公开指针生效、HTTP 下载核验通过。
5. 如果显示“已可见、下载核验未通过”，记录页面状态，使用“重新核对公开下载”。不要反复重新上传、覆盖旧包或把它记成通过。

## 老师在 DSH 中验收

| 操作 | 预期结果 |
| --- | --- |
| 在管理员发布前刷新市场 | 不出现尚未发布的产品 |
| 发布后点击“刷新市场” | 显示新产品及正确版本，原有已发布产品仍在 |
| 搜索、切换分类、查看详情、返回列表 | 不下载或安装产品，不启用组件 |
| 点击“下载并查看安装确认” | 下载固定版本并核验；显示用途、权限、精确包身份和安装确认，此时仍未安装 |
| 点击“拒绝／不安装” | 不产生安装，不自动重试 |
| 再次准备并确认安装 | 只安装该精确版本，结果为已安装、未启用 |
| 查看并确认启用 | 本轮支持的唯一组件按一次确认启用包与组件；安装确认仍独立保留 |
| 验证实际能力 | 在新对话检查对应 Skill 或工具，执行一个匿名业务样例；仅“组件已加载”不能替代业务验收 |

已有其他版本时，应显示版本冲突或引导到官方详情；本轮不自动覆盖或降级。额外安装脚本授权、兼容性豁免或未知结果应停止，保留提示供维护者检查。

## 拒绝、撤回与异常验收

- 先在老师端停留于安装确认页，再由管理员明确撤回该产品。老师随后点击旧确认，应被拒绝，不能沿用缓存包继续安装。刷新后该产品不再作为新安装入口出现。
- 撤回不卸载已安装产品，也不删除老师的课程或其他成果；保留旧固定包和操作记录。恢复旧版本必须发布一个新的目录修订，不能覆盖历史文件。
- 在安装进行中或官方结果尚待核对时点击刷新，不得丢失该任务；先处理或核对原操作，再刷新。
- 暂时断开测试 Hub 后刷新，应说明目录不可用或旧数据状态，并停止新的安装与启用；不能静默退回旧目录授权。恢复连接后重新刷新、准备并确认。
- 维护者用隔离测试验证错误签名、过期目录、旧修订重放、包摘要错误和发布中断；不要在真实 Hub 上人为损坏发行文件。

## 记录与通过条件

每个场景分别记录“通过／失败／未测”，附产品与市场版本、时间、预期、实际结果和不含个人资料的截图。发生错误时记录页面原因码；不要附密码、会话令牌、模型 Key、签名私钥或完整个人配置。

发布、浏览与拒绝分支、固定包安装且默认未启用、单独启用、真实能力调用，以及撤回后的旧确认失效均通过，才能把原生整体验收标为通过。模型输出与教学效果另行由老师审阅。

技术契约、部署命令与已知限制见 [实施说明](qcu-hub-market-publication.md)。本轮还需区分原生 DSH／实际 Hub／教师业务验收；本地测试通过不代表这些步骤已执行。
