# 统一团队模型样板计划

2026-11-12，用户确认先用深度研究做一版看效果。

## 本轮验收

1. 在原专家团工作室从深度研究模板创建“我的团队”，修改角色名称、身份、职责、输出要求、工具，以及步骤和依赖，保存重开不丢失。
2. 安装来源只是模板来源，工作副本可编辑；保留来源版本，不改写市场安装包。原有自建团队可显式复制进同一新模型，原配置和历史不做自动迁移。
3. 统一工作室中的配置、任务预览、运行进度、步骤输出、停止与报告下载；不再将整个团队转成一句技能调用后跳到主会话。
4. 程序调度独立步骤代理，审稿按严格结构化结果判断；有上限地修订与复审，失败不强制通过。
5. 提供明确标注的无模型流程演示，以及单独确认的真实原生执行。不得用演示结果声称真实检索、数学或教学质量通过。

## 结构

统一定义：团队名称/说明、来源、角色（名称/身份/职责/输出/工具/高级指令）、步骤（角色/依赖/审核及修订规则）、最终输出和运行限额。V1按拓扑顺序串行执行；不提供虚假的并行配置。

模板：7个角色，6个主步骤——目标整理、规划大纲、资料研究、独立审核与必要修订、报告撰写、交付整理。审核节点最多2轮修订，每轮由另一个角色修订后再审。角色和步骤均可编辑。原始第三方Markdown只作来源参考，不充当程序流程定义。

工作副本与运行记录增量保存到所选工作区 `.qcu-expert-teams/unified/`，独立于旧 `state.json`。新旧定义经显式适配进入统一模型；原有数据不自动覆盖。运行冻结配置、模型、输入和来源。修改团队不会改变已有运行快照。重启时将未完成任务标为中断，不自动重跑。

执行器使用官方 `agents.create`、作用域 `systemPrompt.section` 与 `tools.restrict/guard`，保持原生审批；每个步骤新建独立代理，不让主理人模拟所有成员。严格限制所选工具，保留原生会话ID以便审批和追溯。模型步和工具调用设置共享上限，超时和取消会传给代理。

默认只由Host向任务专属目录保存报告，不自动对外发送、部署或安装依赖。工具能力按当前原生实例可用情况检查，缺失则不启动真实任务；不会把需要联网的方案悄悄降级为纯文字。

## 实施顺序

1. 统一定义、深度研究模板、旧自建团队适配器及工作副本存储。
2. 可编辑角色/步骤界面、任务预览、明确区分的演示流程。
3. 原生步骤执行、审核修订、预算、停止、可追溯步骤与报告。
4. 回归测试与实际浏览器验收；先交付可审阅的样板，验证后再更新运行实例。

## 暂不包含

全量模板转换、自动合并上游更新、旧历史批量迁移、断点续跑、并行执行、Word/PPT导出及全平台安装包。当前版本保留来源版本，为后续显示更新差异留数据，不提前实现自动覆盖策略。

真实模型端到端结果、检索来源质量和教师业务验收单独记录；不因SDK和合成测试通过而写成完成。
